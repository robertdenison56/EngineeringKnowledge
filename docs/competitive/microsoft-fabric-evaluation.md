## 1. Why this comparison matters now

Early-2025 Fabric was a data-warehouse/BI consolidation play (OneLake + Synapse workloads + Power BI) with no graph, no ontology, and no agent story beyond "AI skills" in preview. That Fabric was irrelevant to EKG. The 2026 Fabric is not:

- **Ignite (Nov 2025)** announced **Fabric IQ** — "the semantic foundation for enterprise AI": an ontology item (entities, typed relationships, rules, data bindings to OneLake), a graph engine under it, and the "IQ" positioning family (Work IQ / Fabric IQ / Foundry IQ).
- **FabCon Atlanta (Mar 2026)** made MCP the developer surface: local Fabric MCP (preview), Microsoft-hosted **Remote MCP** with Entra auth (preview), OneLake catalog APIs feeding it, plus OneLake security (row/column-level) reaching GA.
- **Build (Jun 2026)** declared the umbrella GA: **Graph GA (GQL, ISO 39075)**, data agents in **M365 Copilot GA**, **Foundry IQ knowledge bases GA**, OneLake catalog inside Foundry GA, SharePoint/OneDrive shortcuts GA, "Skills for Fabric" open-sourced for Claude/Cursor/Copilot coding agents, and **Web IQ** (Bing grounding-as-API) in preview.

Microsoft now sells, as first-party products, three of the four things EKG's PRD promises: a knowledge graph over enterprise data, per-user permission-trimmed agent grounding, and multi-assistant distribution. The fourth — understanding what is actually *in* an engineering document — it does not sell, and that gap is load-bearing for everything below.

A status-discipline warning up front: Microsoft's "GA" claims here are slippery. "Fabric IQ GA" (Build 2026) covers the umbrella; **the ontology item itself is still preview** as of the July-2026 docs, data-agent-in-Copilot docs still carried preview banners three weeks after the GA announcement, and Remote MCP was announced with missing docs/endpoints. Treat each capability's status individually; this document does.

**Positioning statement (theirs, reconstructed):** for enterprises standardizing on Azure/M365, Fabric is *the* unified data platform whose semantic layer (IQ) makes agents "understand the business" — differentiator: everything in one governed lake, one security model, one capacity bill, agents distributed through the Copilot surfaces employees already have. Proof points: OneLake ubiquity, Entra-enforced identity end-to-end, ISO-standard GQL, Purview governance.

## 3. Overlap map — honest feature comparison

Rated for the buyer that matters to us: a 50–500-person AEC firm that lives in drawing sets, spec books, RFIs, and M365, holds EOR liability, and increasingly also runs Procore/ACC. (Scale: Strong / Adequate / Weak / Absent.)

| Capability (buyer-relevant) | EKG today (`b29ca77`) | Fabric (+ Foundry IQ) |
|---|---|---|
| **AEC document understanding** — drawing sheets, title blocks, callouts, cross-sheet references, MasterFormat anchors, CAD vector parsing | **Strong** — the product's core; deterministic parser + vision fusion (ADR 0007/0008), sheet/page anchors, date-proof spec-section detection validated on a 29-PDF Caltrans corpus (353→0 false anchors) | **Absent** — data agent rejects PDFs outright; Foundry IQ chunks documents generically with no sheet, callout, or spec-section semantics; nothing AEC-aware anywhere in the stack |
| **Citation-grade provenance** | **Strong** — page/sheet-level anchors on every passage, two-source grounding of model descriptions, verified/unverified lifecycle, immutable audit incl. denials | **Weak** — ontology has concept-level provenance; Foundry IQ returns source references; but **M365 Copilot's orchestrator "re-reasons over and rewrites" agent output (Microsoft's own docs: "some level of change is inevitable")** — fatal for EOR-liability citation |
| **Per-user permission trimming** | **Adequate** — per-request identity (dev JWT + Entra RS256/JWKS), ACL trimming at the store, tenant isolation, now role-gated writes; *but Entra app registration/E2E still pending* | **Strong** — Entra end-to-end, OneLake row/column security GA, RLS/CLS honored by data agents, Foundry IQ query-time trimming (with per-source caveats), Purview labels |
| **Knowledge curation workflow** — verified/unverified, curator roles, supersede/dedup, undo | **Strong** — the workspace app is built around it | **Absent** — nothing equivalent; ontology "curation" is data modeling, not knowledge review |
| **Graph & ontology infrastructure** | **Adequate** — purpose-built SQLite graph store, typed relationships, focus lenses; no GQL, single-node | **Strong** — GA GQL graph at billions-of-edges scale; ontology item (preview) with rules and NL2Ontology |
| **Assistant distribution** | **Adequate** — MCP gateway shipping for Claude (stdio + remote HTTP) and Codex/ChatGPT; Copilot path designed, blocked on Entra registration + public HTTPS | **Strong** — native surfaces in M365 Copilot/Teams (GA), Copilot Studio, Foundry, Agent 365; the default answer inside any Microsoft shop |
| **Cross-vendor source coverage** (M365 *and* Procore/ACC/Bentley) | **Adequate** — CLI ingestion of anything on disk incl. OneDrive-synced trees (walk hardened for cloud placeholders, `87b0a4b`); Procore/ACC connectors on roadmap | **Weak** — Procore signed with AWS (Aug 2025) and bought Datagrid; Autodesk integrations route through Foundry/Copilot Studio *via Autodesk's APIs*, not OneLake; no Bentley/Fabric story found |
| **Time-to-value / cost for a mid-size firm** | **Adequate** — single binary + SQLite, no capacity math; but no Dockerfile/IaC yet (deployment story is our real gap) | **Weak** for this buyer — capacity-unit economics (throttling, smoothing, "phantom CU consumption", F64 viewer-license cliff), ontology modeling effort before value, five-workload learning curve |
| **Enterprise data-platform breadth** (BI, warehousing, real-time, governance) | **Absent** — deliberately | **Strong** — the actual product |

Two honest asymmetries the matrix hides. First, Microsoft's identity/governance substrate is *deeper* than ours and GA — our parity claim ("per-user trimming") is table stakes to them, not a differentiator; what differentiates us is *what* gets trimmed (curated, cited AEC knowledge vs. lake tables). Second, our operational maturity lags badly: the 07-25 repo review's "there is no outside" finding (no Dockerfile, no migrations, no tags) is untouched, and a Fabric-vs-EKG bake-off in a Microsoft-first firm would surface that instantly.

## 4. Where the new Fabric does not reach (the wedge, verified)

1. **It cannot read the documents that carry AEC liability.** The data agent's own docs list .pdf/.docx/.txt as unsupported and lakehouse *files* as unreadable (tables only). SharePoint shortcuts move PDFs into OneLake, but "grounding" on them is delegated to Foundry IQ / AI Search generic chunk-and-embed. Nobody in the stack knows what a detail callout, a match line, a revision cloud, or "07 84 00" *is*. Our entire ingestion pipeline — and the 353-false-anchor lesson that shaped it — has no counterpart there.
2. **Its citation chain breaks exactly where ours is strongest.** Microsoft documents that the M365 Copilot orchestrator rewrites data-agent responses. An EOR cannot stamp "some level of change is inevitable." EKG's answer — deterministic anchors, two-source grounding, unverified-by-default machine content, audited denials — is the liability story, and it just got stronger (this week's `4c13738` closed the last known fabricated-citation class).
3. **Ontology-by-modeling vs. knowledge-by-ingestion.** Fabric IQ assumes someone models entities, bindings, and rules over governed tables (practitioners report substantial effort, capacity throttling during graph processing on an F4, and manual refresh on every upstream change; ontology still preview). AEC firm knowledge lives in documents, not tables; EKG builds the graph *from* the documents.
4. **Cross-vendor reality.** The construction stack is consolidating *away* from any one cloud: Procore→AWS, Autodesk exposing its own APIs, Trimble buying Document Crunch. A Microsoft-only grounding story leaves half the project record out; EKG's neutrality is structural, not aspirational.
5. **Cost shape.** F-SKU capacity + Copilot Credits + per-user Copilot licenses ($30/user/mo class) + Azure Search meters is an enterprise procurement exercise. A 120-person structural firm will not stand up an ontology program; it will buy a tool that reads its spec books on day one.

## 5. Threats, ranked

1. **Foundry IQ "good enough" bundling (now, highest).** Knowledge bases over SharePoint with per-user trimming, GA, one checkbox away for a Microsoft-first firm. It will not cite sheets or parse specs — but for firms that never evaluate deeply, generic RAG + Microsoft trust wins the deal before we're in it. *Counter: lead demos with fabricated-citation failure modes on their own documents; sell the Caltrans story.*
2. **Fabric IQ ontology GAs with document/unstructured bindings (12–24 mo).** The July-2026 "What's next for Fabric IQ Ontology" roadmap post signals expanded integrations. If ontology entities ever bind to *document content* with page provenance, the moat narrows to AEC parsing alone. *Watch trigger: any "unstructured data binding" or "document entity" language in Fabric IQ release notes.*
3. **Autodesk or Bentley picks OneLake (12–24 mo, low probability/high impact).** The MAIRE case shows the appetite (Foundry + Copilot Studio over Forma/Revit APIs, 200+ engineers). Today it routes through vendor APIs, which preserves our cross-vendor role; a native ACC/OneLake mirror would not. *Watch trigger: Autodesk–Microsoft data-platform (not Copilot) announcements.*
4. **M365 Copilot distribution gravity (structural, ongoing).** The Agent Store makes "grounded agent" a checkbox in the tool employees already have. Mitigation is the one already in the PRD: be *in* that surface (declarative agent/MCP into Copilot) rather than beside it — which the review deferred deliberately; the Entra-registration work (G11) is the prerequisite either way.
5. **Preview churn as FUD.** Microsoft's status ambiguity (GA umbrellas over preview cores) lets their sellers claim everything today. Our brief's dated status table is the antidote in competitive conversations.

## 6. Opportunities the new Fabric creates for EKG

1. **Foundry IQ accepts MCP servers as knowledge sources (preview, Build 2026).** This is the single most actionable fact in the research: Microsoft built a first-party socket that an **EKG MCP gateway can plug into**, making EKG the AEC-native knowledge source inside a customer's Foundry agents — distribution *through* Microsoft's stack with our provenance intact end-to-end (their orchestrator consumes our tool results directly rather than re-indexing our corpus). Small spike: point a Foundry IQ knowledge base at the gateway once Entra registration lands.
2. **Microsoft normalized our architecture.** Entra-authenticated remote MCP is now *Microsoft's own* pattern (Remote MCP, Agent 365 first-party MCP tools, data-agents-as-MCP). "An MCP gateway with per-user OAuth" no longer needs explaining to a Microsoft-shop IT department — b1f2d71's OAuth resource-server design is exactly the shape they now expect. This retroactively strengthens the multi-gateway pillar the June evaluation demoted.
3. **OneLake ODSP shortcuts solve *transport*, not *understanding*** — and transport was never our moat. A firm that shortcuts its SharePoint into OneLake still needs something that knows what a spec section is. "We read what Fabric stores" is a cleaner complement line than the 2026-06 "complement, don't replace Copilot" framing, and it inherits their governance story instead of fighting it.
4. **Their practitioners are documenting the pain we avoid.** Capacity throttling from graph processing, phantom CU consumption, manual ontology refresh, the F64 cliff — third-party, citable, current (Feb–Jul 2026). Battle-card material that we did not have to write.

## 7. Strategic implications (build / accelerate / deprioritize / monitor)

- **Accelerate: Entra app registration + real-tenant E2E (G11).** It was already the roadmap's gateway item; this research upgrades it from "Copilot prerequisite" to "prerequisite for the entire Microsoft-ecosystem distribution surface" (Copilot, Foundry IQ MCP sources, Agent 365). Nothing else on the Microsoft front matters until it lands.
- **Build (small, new): a Foundry IQ integration spike** — EKG gateway as an MCP knowledge source in a Foundry knowledge base, provenance surviving round-trip. One day of work once G11 lands; turns the complement story into a demo.
- **Keep the course on: false-citation rigor and curation workflow.** They are the demo-able difference against generic RAG, and this week's work (rotation-true rendering, date-proof anchors, write-authz with audited denials) is exactly the right kind of investment.
- **Deprioritize / don't build:** GQL/graph-scale features (Graph in Fabric owns this; our graph serves citations, not analytics), ontology-modeling UX, any BI/dashboard ambitions, and — reaffirming the 2026-06 evaluation — horizontal connector breadth.
- **Fix the embarrassing gap before it's competitive:** deployment packaging (Dockerfile/IaC/migrations). Losing a bake-off to Fabric on "we couldn't install it" would be self-inflicted.
- **Positioning sentence (updated):** *For AEC firms, EKG is the engineering-knowledge layer that actually reads drawing sets and spec books — page-cited, curator-verified, permission-trimmed — and serves them to every assistant the firm uses: Claude, ChatGPT, and the Microsoft Copilot/Foundry stack itself.*
- **Monitor (quarterly, ~1 hr):** Fabric IQ ontology GA + any unstructured-binding language; SharePoint *mirroring* GA; Foundry IQ MCP-source GA + pricing; Autodesk/Bentley–Microsoft data announcements; digital twin builder revival; Remote MCP maturity.
